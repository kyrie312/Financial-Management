# 云端部署指南（Supabase + Vercel）

这份文档记录「让两台电脑打开同一个网址、数据只有一份」的部署方案与步骤。

## 架构

```
你的电脑 / 手机浏览器
        ↓  https://<项目名>.vercel.app
   Vercel：Next.js 应用（前端 + 后端接口）
        ↓  连接池（PgBouncer, 端口 6543）
   Supabase：PostgreSQL 数据库（免费 500 MB）
```

- **数据只有一份**（在 Supabase），所以两台电脑不存在"同步冲突"，一端改完另一端刷新即见。
- 应用是无状态的：登录状态用 HMAC 签名的 Cookie，任何一台 Vercel 实例都能校验。

## 关键配置

| 配置项 | 值 | 说明 |
|---|---|---|
| Supabase 项目地区 | us-west-2（美国西部 Oregon） | 建成后不可改 |
| 连接方式 | **Connection pooling / Transaction pooler，端口 6543** | 直连地址只有 IPv6，Vercel 连不上 |
| Vercel Function Region | **sfo1（美国西部 圣何塞）** | 与 Supabase 同区域，数据库查询才是毫秒级 |
| Node 版本 | ≥ 22.5（Vercel 上建议 24.x） | 本机脚本用到 `node:sqlite` 做迁移 |

## 环境变量（Vercel → Project → Settings → Environment Variables）

| 名称 | 值 | 必需 |
|---|---|---|
| `DATABASE_URL` | Supabase 连接池连接串（含密码） | ✅ |
| `SESSION_SECRET` | 一串随机字符（≥16 位），用于签名登录 Cookie | ✅ |
| `APP_PASSWORD` | 首次初始化账号用的密码；之后在网站「设置」里改 | ✅ |

> 改了 `SESSION_SECRET` 会让所有设备需要重新登录（数据不受影响）。
> 数据库密码泄露时：Supabase → Project Settings → Database → Reset database password，然后同步更新这里。

## 部署步骤

1. 代码推到 GitHub 仓库（`.env.local` 与 `data/` 已被 `.gitignore` 排除，不会上传）
2. Vercel → Add New → Project → Import 该仓库
3. **Settings → Functions → Function Region 改成 `sfo1`**
4. 填上面三个环境变量 → Deploy
5. 打开网址，用 `admin` + `APP_PASSWORD` 登录验证

## 首次把本机数据搬到云端

```powershell
# 生成随机 SESSION_SECRET（可选，替换 .env.local 里的值）
# 在项目目录执行：
node scripts/migrate-to-supabase.mjs          # 追加导入（自动去重）
node scripts/migrate-to-supabase.mjs --reset  # 清空云端记录后完整导入
node scripts/setup-cloud-user.mjs             # 在云端创建登录账号（幂等）
```

`migrate-to-supabase.mjs` 会自动读取 `.env.local` 里的 `DATABASE_URL`。

## 自测（对着云端数据库跑）

```powershell
powershell -File scripts/smoke-test.ps1          # 接口 55 项
powershell -File scripts/smoke-life-adjust.ps1   # 生活费改总额 24 项
```

两套脚本都会自动清理自己写入的数据（生活费那套还会先备份、测完还原）。

> 注意：本机连美国数据库时，每请求约 200–400ms（跨太平洋），所以自测比本地慢很多；
> 线上部署在 Vercel（同区域）后，页面响应是毫秒级。

## 已知取舍

- **本机运行 `npm run dev` 也连云端数据库**，所以断网时只能看、不能写。
- Supabase 免费项目「一周完全不活跃会被暂停」，官方说明每天几次请求就足以避免；暂停后一键 Resume，数据不丢。
- 免费版不含自动备份：定期用页面右上角「导出」存一份 CSV 到本地即可。
